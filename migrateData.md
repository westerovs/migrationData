# 📦 `migrateData.js` — система миграции данных сохранения игрока

Этот модуль используется для **мягкой миграции пользовательских данных** к актуальной структуре.  
Он позволяет адаптировать старые сохранения под новую схему данных без потери пользовательских значений.

---

## 🧠 Что делает `migrateData`

- Обновляет данные сохранения на основе текущего шаблона (`template`)
- Переносит поля, если они переместились во вложенные объекты (`fieldMoves`)
- Поддерживает вложенные объекты и вложенную миграцию
- Логирует и игнорирует устаревшие поля
- Устанавливает `version` только на верхнем уровне

---

## 📁 Структура

### `fieldMoves`

```js
const fieldMoves = {
  partIndex: ['savedLevel'],
}
```

Карта перемещения полей из старой структуры в новую.

- **Ключ** — имя поля в старом `oldData`
- **Значение** — массив, указывающий путь в новом `newData`, куда следует перенести поле

#### Пример (partIndex из тела объекта переносим в savedLevel):

```js
partIndex: ['savedLevel']
```

превратится в:

```js
// savedLevel: {levelIndex: 0, skinIndex: 1, partIndex: 1}
newData.savedLevel.partIndex = oldData.partIndex
```

---

### `setDeep(obj, path, key, value)`

```js
const setDeep = (obj, path, key, value) => {
  let target = obj
  for (const segment of path) {
    if (!target[segment]) target[segment] = {}
    target = target[segment]
  }
  target[key] = value
}
```

Утилита, создающая вложенные объекты по переданному пути и устанавливающая значение.

---

### `migrateData(oldData, template, currentVersion, isTopLevel = true)`

Главная функция миграции.

#### Аргументы:

- `oldData` — данные старого формата
- `template` — эталонная структура, к которой нужно привести `oldData`
- `currentVersion` — актуальная версия, которую нужно установить
- `isTopLevel` — внутренний флаг, указывающий на верхний уровень вызова

#### Поведение:

1. Обходит ключи в `oldData`
2. Если поле указано в `fieldMoves` — переносит его во вложенность
3. Если поле находится в `template.options` — переносит в `newData.options`
4. Если поле существует в `template` и является объектом — рекурсивно вызывает `migrateData`
5. Если поле есть в `template` — перезаписывает значением из `oldData`
6. Все прочие поля — игнорируются, выводится `console.warn`
7. На верхнем уровне добавляется `version`

---

## ✅ Пример использования

```js
const playerData = migrateData(dataFromServer, PlayerStats, 0.002)
```

---

## 🧼 Рекомендации

- Добавляй новые перемещения только в `fieldMoves`, не внося хардкод в `migrateData`
- Храни шаблон (`template`) отдельно и не мутируй его напрямую
- Обновление версии выполняется автоматически только на верхнем уровне
